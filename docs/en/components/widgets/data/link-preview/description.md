# Link Preview

| Field | Value |
|-------|-------|
| **Category** | `data` |
| **Inherits from** | `base` |
| **Variants** | `card`, `compact` |
| **States** | `loading`, `ready`, `unavailable` |
| **Gestures** | none – gestures are added by the frontend, not by the component (ADR 0037) |
| **Animations** | `fade-in` |
| **Related** | `card`, `image`, `link`, `message-bubble`, `hover-card` |
| **Status** | skeleton |

## Description

A link preview is a preview card for a link, generated by the **sender** and attached to the message. The reader never fetches the target.

## Purpose

- Preview of a link inside a message
- Privacy-preserving: no tracking request from the reader
- Click opens the target after confirmation

## Variants

| Variant | Description |
|---|---|
| **card** | title, description, image, site |
| **compact** | title and site in one line |

## Features

- Title, description, image, site name
- Preview data comes from the message, not from the network
- Click goes through the host (confirmation for external targets)

## Data binding

Binds an ActivityStreams `Link` / `Page` as attachment ⚠️ (not standardised for all transports). Register (ADR 0023): `Link → link-preview | text`.

## Distinction

- **Do not confuse with** [card](../../containers/card/): the card is a generic container; this one binds the link data.
- **Do not confuse with** [hover-card](../../overlays/hover-card/): that appears on hover; the preview is part of the content.
- **Do not confuse with** [embed](../../../workbenches/special/embed/): no foreign content is loaded.

## Best Practices

- Never fetch remote images; use only what the sender attached.
- Show the real target domain.
- Leave the preview off for unencrypted conversations if the host requires it ⚠️.

## Blinc note

Partly in Blinc (`cn::card`). Built in our layer because of the data binding. Backlog id: none ⚠️.

## Open points
