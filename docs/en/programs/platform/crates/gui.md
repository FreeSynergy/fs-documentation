## Blinc: status from the author (request 2026-11)

- **Gestures:** "A handful of gestures are supported. However, I am happy to support any missing gestures." → missing gestures (general swipe recogniser, two-finger pan/rotate) can be requested from the author. The Android and iOS implementation has not yet been confirmed in detail by the author, but multi-touch and pinch are present on both platforms in the code (see the row above).
- **Components:** `blinc_cn` covers the common ones; the rest are tracked as issues in **git-bug** (not GitHub issues — check with `git-bug bug --status open` following the repository's `./scripts/` workflow).
- **Release 0.6.0 in progress — with builder API changes:**
  - **CSS-first** for visual styling ✅ (exactly our direction)
  - Stateful closures are dropped → **property bindings with signals**, SolidJS-style `Computed`/`Effect` ✅ (fine-grained reactivity stays, no VDOM)
  - Performance and cross-platform stability (macOS, Windows, Linux)
- **Consequence for us:** do not dig deep into 0.5.x — build the prototype directly on 0.6.x; otherwise the API break would mean double work.

## Conclusion / decision (status 2026-11)

**Blinc is the main favourite.** Reason: it is the only candidate that meets all three core requirements at once (real CSS, canvas kits for whiteboard and maps, and no VDOM on all platforms including mobile). The author is directly reachable and open to extensions (gestures, components) — this lever exists for no other crate. Remaining risks: small bus factor, the 0.6.0 transition, web only as preview.
**Safeguard:** keep watching Dioxus + Blitz as a fallback (best CSS, but canvas gap); use Makepad's gesture design as a reference for Blinc extensions.

## Combinability: Blinc + gestures from Makepad/Slint?

**Directly linking two GUI frameworks does not work** — Blinc and Makepad each bring their own render pipeline, event and layout systems and their own main loops; mixing two in one app means duplicate windows and events and rendering conflicts. Makepad's gestures are also deeply integrated into its event camera (`TwoHalfWindow` model, `Hit`/`GestureResult`) and are not exported as a standalone crate.

**Realistic paths:**
1. **Ask the Blinc author** (preferred): gesture recognition is largely framework-independent mathematics (finger distances → pinch/zoom, velocity/direction → swipe, timer → long-press). Makepad is MIT/Apache-2.0 — its gesture logic may serve as a reference and be moved into a `blinc_gestures` model. This fits Blinc's state-machine design: gestures as their own state types with `StateTransitions`.
2. **Read reference code instead of copying it:** use Makepad's `makepad-widget-system` (gesture structure) and Slint's `MultiPointTouchArea`/`Flickable` (Rust, clean separation of gesture → property update) as blueprints.
3. As a last resort, build a gesture layer **on top of** Blinc (a separate crate in the workspace that collects Blinc pointer events and feeds the state machines) — possible without outside help, but with multi-touch under Blinc priority (⚠️ verify first!) potentially blocked.
